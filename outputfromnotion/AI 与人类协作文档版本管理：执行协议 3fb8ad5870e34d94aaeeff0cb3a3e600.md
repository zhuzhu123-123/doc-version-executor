## 一、目标与适用范围

本协议是可被不同 Workflow 和 Agent 调用的通用版本管理流程，也是上一层 Workflow 的最后一个必做步骤：每次正式修改文档后，在文档顶部的版本管理表留下一条准确的版本记录，并建立一份与文档一模一样的副本，以便修改出错时凭副本恢复。

版本管理没有完成时，本轮版本不成立，本轮工作流没有执行完全，不得宣布本轮完成，也不得在此基础上开始下一轮修改。

本协议不规定上一层 Workflow 怎样写作、审阅、核验来源或采用什么输出格式，也不重新核验或改写其业务内容。普通讨论、临时回答和不需要长期存档的内容不调用本协议。

## 二、触发

上一层 Workflow 完成本次已确认的执行范围并通过自身全部验收后，自动启动本协议，不要求人类再次提交、确认或提醒。上一层未完成或验收未通过时，不启动。

## 三、输入

- 文档，包括顶部的版本管理表；
- 本次操作说明：修改开始前人类确认过的说明。上一版那一行的“下一版操作说明”和新一行的“当前版本操作说明”都按它填写。

缺少本次操作说明时，说明不知道这一版改了什么，按第八章记为版本管理失败，不得自行编写。

## 四、角色与责任

| 角色 | 责任 |
| --- | --- |
| 上一层 Workflow | 完成修改和验收后，自动调用本协议。 |
| 执行器 | 由程序按本协议完成全部步骤；每一步完成后自行检查，出错在同一次执行内纠正。 |
| 人类 | 正常版本管理不需要确认；只在用旧副本覆盖文档前确认恢复范围。 |

文档和副本的读取、写入、读回和比对必须由程序执行，不得依靠模型记忆、转述或目视对比。工具返回失败时，不得当作已经完成。

## 五、执行步骤

每一步完成后立即检查，检查通过才进入下一步。

| 步骤 | 做什么 | 完成后检查 |
| --- | --- | --- |
| 1. 核对输入 | 取得第三章全部输入。 | 本次操作说明不为空。 |
| 2. 读取版本管理表 | 读取全部已有行，并保存原文。 | 读取成功。 |
| 3. 确定版本编号 | 新编号＝最近一个已成立版本加一。 | 新编号在表中不存在；不覆盖、不重排已有编号。 |
| 4. 建立空副本页 | 在版本副本存档页下建立空页面，标题为“第N版副本｜文档标题”。 | 标题正确（第N版副本｜文档标题）；取得副本链接。 |
| 5. 写入版本记录 | 先把最近一个已成立版本那一行的“下一版操作说明”按本次操作说明填写（第1版没有上一版，跳过）；再在表末尾追加一行：版本填第N版；当前版本操作时间填写入时的时间；当前版本操作人填执行本次修改的一方；当前版本操作说明按本次操作说明填写；当前版本影响位置按实际改动填写；下一版操作说明留空；文档副本存档链接填第4步的链接。 | 程序读回：新行编号、各列内容和链接均正确，“下一版操作说明”为空；上一版那一行只有“下一版操作说明”一格变化；其余旧行与第2步保存的原文逐字一致。 |
| 6. 写入副本 | 把文档全部内容（含版本管理表）原样写入副本。 | 程序独立读回副本，与文档逐字比对，完全一致才通过。 |
| 7. 输出结果 | 按第六章输出。 | 第七章全部条件满足。 |

副本写入不得摘要、压缩、删减、留空或人工重写，不得加入执行器说明、模型解读、评论或标注。副本统一建在版本副本存档页下，不挂在文档下面；文档只通过版本管理表的副本链接进入历史版本。

逐字比对的方法：对文档和副本做同一标准化（统一换行、去除行尾空白、剔除子页面引用块，链接只保留所指向的页面；打开是同一个页面就算一致），各计算一次 SHA-256 哈希，两个哈希完全相同才算一致。多页文档逐页计算哈希，再按固定顺序汇总为总哈希。哈希只用于当场比对，不写入版本管理表。

## 六、输出

- 文档：上一版那一行的“下一版操作说明”按本次操作说明填写；版本管理表末尾新增一行本版本记录。
- 副本：除标题外与文档一模一样，包括版本管理表；建成后不再修改。文档以后再修改时，建立下一版和新的副本。
- 执行结果：“版本成立”，或“版本管理失败＋失败步骤＋已完成部分＋待处理问题”。

## 七、验收

以下条件全部满足，才输出“版本成立”，本轮工作流正式结束：

- 新版本编号正确且不重复；
- 本版本记录除“下一版操作说明”外全部填写，“下一版操作说明”为空，副本链接指向本版副本；
- 上一版那一行的“下一版操作说明”已按本次操作说明填写；
- 副本由程序独立读回，除标题外与文档逐字一致；
- 除上一版那一格外，所有旧行没有任何变化；
- 没有未解决的异常。

## 八、异常处理

### 1. 重试规则

读取、副本写入、读回、比对以及版本记录写入出现可恢复错误时，同一步骤最多尝试3次（首次1次＋重试2次），中途成功即进入下一步。重试使用同一版本的执行代码和同一套检查标准，不得临时改写代码、放宽标准或改写文档。写入结果不明确时，先读取实际状态，确认上次是否已经写入，不得重复写入。

### 2. 各类情况

| 情况 | 处理 |
| --- | --- |
| 本次写入的版本记录或上一版那一格有错（编号重复、内容或链接错误） | 在同一次执行内改正，不新建版本。 |
| 副本与文档不一致 | 清空副本完整重写，再比对。 |
| 读回失败或无法计算哈希 | 按重试规则重试；不得改用目视或转述代替。 |
| 第3次仍未解决 | 停止，记为版本管理失败。 |
| 缺少本次操作说明 | 停止，记为版本管理失败。 |
| 执行中文档发生变化 | 停止，记为版本管理失败；返回上一层重新验收后再启动。 |
| 找不到或打不开本协议、文档、版本管理表或存档页，或者没有修改权限 | 停止，记为版本管理失败；不得凭记忆执行，也不得换到别的位置建副本。 |

停止类情况不因剩余尝试次数继续执行。

### 3. 异常记录

版本管理失败时，在版本管理表记一行异常：本次已写入的版本记录直接改为异常行；尚未写入时，在最新一行之下追加异常行。每次失败只记一行，中间尝试不单独记。

异常行七列依次写：“异常”、发生时间、操作人、失败步骤、已完成部分、待处理问题、副本链接（没有则写“无”）。异常行不占版本编号；下一个成立的版本追加在异常行之下，编号接最近一个已成立的版本。

版本管理表本身无法写入时，只在执行结果中输出失败步骤、已完成部分和待处理问题。

### 4. 恢复文档

文档被错误修改需要恢复时：立即停止修改 → 记录错误影响位置 → 找到最近可靠的版本副本 → 人类确认恢复范围 → 恢复文档 → 记录恢复结果。未经人类确认，不得用旧副本覆盖文档。

## 九、审计留痕

- 版本管理表固定七列：版本、当前版本操作时间、当前版本操作人、当前版本操作说明、当前版本影响位置、下一版操作说明、文档副本存档链接。
- 已成立的版本行和异常行都是历史，一经写入不得修改、删除或重新组织；正文修改要求不得作用于旧行。每次执行只能改动本次自己写入的那一行，以及上一版那一行的“下一版操作说明”（按本次操作说明填写）。最新一版的“下一版操作说明”为空是正常状态。
