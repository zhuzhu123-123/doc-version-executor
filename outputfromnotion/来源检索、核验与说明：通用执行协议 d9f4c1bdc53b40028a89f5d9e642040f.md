## 一、目标｜通过可执行措施取得可用来源

本协议用于围绕具体正文主张检索、核验和说明来源。它可以独立执行，也可以被文章创作、研究、审稿、多来源知识整理或其他Workflow使用。

本协议解决的核心问题包括：模型可能编造链接、候选来源只在主题上相近、转载被误当成正式来源，以及页面未显示的信息被模型自行补写。正文是否歪曲或扩大来源内容，由使用来源结果的写作与审稿Workflow负责。

这些已知问题通过正常流程中的链接入口、页面访问、字段提取、主张拆分、相关性判断和验收措施处理。工具、权限、访问、解析和写入等无法完全由流程提前消除的运行故障，进入异常处理。

## 二、适用范围与触发条件

本协议适用于：

1. 为正文中的事实、观点、数据、人物发言、政策、产品信息或现实案例寻找来源；
2. 核验已有链接是否真实、相关和可用；
3. 追溯转载、摘要、剪辑或聚合内容的正式发布页面；
4. 补充、替换或重新核验已有来源。

个人感受、个人经历和明确标注为创作者判断的内容，不自动要求外部来源。执行前必须明确需要核验的正文主张；没有具体主张时，不搜索一批主题相近但无法对应正文的链接。

## 三、输入、职责与判断结构

### 1. 必要输入

- 需要核验的具体正文内容；
- 已有候选链接、标题、作者或其他线索；没有现成线索时，由AI从正文主张开始检索。

时间、语言、地区、来源类型和查证范围只在人类明确提出时作为任务限制。可用搜索、读取和数据库工具属于系统运行条件，由AI执行前检查。

### 2. AI职责

1. 先明确完整检索对象；高度相关来源不足时，按问题、原因、措施、案例和结果形成必要的检索方向；
2. 搜索、追溯并实际访问候选页面；
3. 提取来源信息和与当前主张直接相关的原文内容；
4. 判断候选来源可用、不采用、未找到或受限；
5. 只交付通过核验的来源，并如实返回未完成范围。

### 3. 问题、措施、正常分支与异常

- **已知问题：**转化为正常步骤中的预防、限制和验收措施；
- **正常分支：**候选相关或不相关、可用或不可用、找到或未找到、信息完整或部分缺失、来源一致或冲突；
- **真正异常：**工具超时、权限不足、服务故障、文件解析失败、并发修改、写入失败或状态丢失。

异常处理负责保护当前运行、重试、保存状态或安全停止；高频异常必须进入后续产品分析和版本改进，不能长期代替正常流程设计。

## 四、正常执行流程｜从正文主张到来源结果

### 1. 先搜索完整对象，必要时形成检索方向

根据需要来源的正文内容，先明确完整问题、关键术语、已知对象以及必要的时间、地点、人群和范围。系统首先搜索能够直接覆盖完整对象的高度相关来源，不为了使用固定结构而放弃更完整的证据。

完整搜索得到的高度相关来源不足，或者当前对象包含多个需要分别查找的部分时，再形成五个检索方向：

- **问题：**当前具体出现了什么困难；
- **原因：**为什么会出现或反复出现；
- **措施：**可以采取什么动作；
- **案例：**是否有产品、团队、机构或研究处理过相近情况；
- **结果：**相关措施实施后产生了什么效果。

五个方向用于帮助AI决定继续搜索什么，不是把正文拆成原子事实，也不要求每个方向分别取得一篇来源。一份来源可以覆盖一个或多个方向；没有必要的方向不强制补齐。

### 2. 搜索候选来源

针对完整对象或必要的检索方向组合关键词，优先寻找正式页面、原始材料或可追溯记录。不得先堆积主题相近的链接，再反过来拼接正文。

必须优先寻找正规来源。正规来源有明确的发布机构或署名作者，并对内容负责，例如期刊、政府部门和公共机构、正规新闻媒体和企业官方渠道。没有署名也没有发布机构、来路不明的小网站，属于不够正规的来源。

返回“未找到可核验来源”前，至少应：

1. 调整关键词、同义表达或必要语言；
2. 根据已有结果中的标题、作者、机构和编号继续追溯；
3. 尝试官网、正式目录、原始发布页或其他可访问入口。

具体轮数和时间预算由任务风险及测试结果决定。

### 3. 取得并保存候选URL

正式URL只来自检索工具、正式数据库或目录、人类输入以及已经存在的可靠来源记录。保存实际URL、检索标题、域名、来源入口和检索时间；模型不能根据标题自行拼接URL。

每一次搜索和页面访问都由代码执行，并由代码写入工作记录：检索词、检索时间、返回的链接、打开过的页面和访问结果。AI不能自行搜索、访问页面或改写工作记录。

### 4. 判断是否原始出处，并追溯原始出处

先确认页面真实、内容与正文直接相关，再判断它是否原始出处：

- **是：**页面就是最初发布这项内容的地方；
- **不是：**页面注明内容来自别处，或者明显是在转述；
- **无法确认：**页面没有写明内容来自哪里，也看不出是否转述。

“不是”和“无法确认”时，按渠道寻找原始出处：

| 渠道 | 去哪里找 |
| --- | --- |
| 期刊、学术会议、大学学位论文库、预印本网站 | 用标题或作者查询Crossref等论文数据库，取得DOI，再打开出版社页面；同时查清是预印本还是正式发表版本，以及是否有更新或撤稿。 |
| 政府部门、公共机构、研究机构 | 用文件名、编号和日期，在发布机构官网目录中寻找正式页面或PDF。 |
| 新闻媒体 | 根据报道中提到的报告、数据、采访或声明，寻找原机构、原采访或原数据。 |
| 企业 | 技术资料在官方文档、发布说明、代码仓库、Issue或Commit中寻找与具体版本对应的正式记录。 |
| 出版社 | 用书名、作者和ISBN，在出版社官网的图书页面和图书馆目录中核对，并确认版次。 |
| 个人网站或博客平台 | 逐个打开文中给出的链接和参考资料；文中提到报告、论文或数据时，按上表对应渠道的路径寻找；再用标题和文中原句搜索，找到最早发布的页面。 |
| 社交媒体 | 转发或搬运的内容，打开原帖或原发布者的账号；截图，用截图中的账号名、标题和原句搜索原文；转述某人讲话的，寻找此人的官方账号、原视频或原音频。 |
| 论坛 | 逐个打开发帖人给出的链接和引用；用帖子中的原句搜索更早的发布；提到报告或数据时，按上表对应渠道的路径寻找。 |
| 其他 | 写明具体是什么渠道，记录为产品问题，在后续版本中补充寻找路径。 |

**停止追溯：**找到原始出处，或者上表对应的路径已经全部完成。

**找到原始出处时：**原始出处作为正式来源，转述页面不再作为来源交付。

**找不到原始出处时：**使用已经找到的来源中最正规的一个，在来源说明中写明是否原始出处、注明的出处和追溯情况。最正规的来源仍然不够正规时，该来源的状态为“需人工核查”。

**追溯情况由代码根据工作记录生成。**标注为“不是”或“无法确认”的来源，工作记录中必须已有对应的追溯步骤，代码才允许交付。

### 5. 实际访问并提取信息

打开候选页面，确认页面存在且对象正确。从页面或正式元数据提取标题、链接、来源、作者、发布时间、是否原始出处和正文；页面没有标题时，由代码取正文开头文字代替。没有显示的信息如实记录为“未显示”或“无法确认”，不能使用模型常识补写。

读到的范围由代码根据实际取得的文字填写：全文、只有摘要，或部分正文并写明是哪一部分。

页面需要账号或付费，只能读到摘要或部分正文时，按以下顺序处理：

1. 先寻找同一来源的合法免费全文，例如作者发布在预印本网站或学校论文库中的版本；找到后按全文核验；
2. 找不到时，保留该来源，状态为“部分可确认”，继续寻找能够读到全文、并支持同一正文主张的其他来源；
3. 找到后，能读到全文的来源作为正式来源；只读到部分内容的来源列入部分可确认结果，不混入合格来源；
4. 完成本章第2节规定的检索动作后仍没有全文来源时，交付只读到部分内容的来源，并写明读到的范围。正文主张只能依靠已经读到的内容；需要依靠未读到内容的主张，不能写成该来源支持。

拥有账号的人类可以自行打开全文，或者把文件交给AI按本协议核验。

### 6. 提取与当前主张相关的主要内容

相关性不能只根据标题、摘要或主题判断。读取原文后，写清楚来源主要讲了什么，以及其中哪些内容与正文主张直接相关；保留原文中的时间、对象和范围，不额外生成“可以证明什么、不能证明什么”字段。

### 7. 判断候选结果

每个候选来源进入以下正常结果之一：

- **可用：**页面可确认，来源信息足以说明，原文存在与当前主张直接相关的内容；
- **不采用：**页面真实但内容无关、过度重复，或只有传播价值而没有本次核验价值；
- **继续追溯：**当前页面不是原始出处或无法确认，仍有可追溯的线索，按本章第4节继续追溯；
- **部分可确认：**只读到摘要或部分正文，或者部分字段受限，只能交付已经取得证据的范围，按本章第5节处理；
- **未找到：**完成约定检索动作后仍没有可核验来源；
- **来源冲突：**多个真实来源给出不同结论，分别保留相关内容和差异；
- **需人工核查：**页面真实、内容与正文直接相关，但只找到不够正规的来源；照常完成来源说明，由人类判断是否采用。

### 8. 生成来源结果

合格来源按照第六章格式输出。未采用、未找到、部分可确认、需人工核查和冲突结果分别说明，不混入合格来源列表，也不包装成已经核验完成。

## 五、来源怎么写

“来源”用一句话写清三项内容：在哪个渠道发布、是什么内容、这个渠道是什么性质。例如：

- 《Journal of Monetary Economics》上的一篇期刊论文（Journal of Monetary Economics：据其官网介绍，发表现代宏观经济学广泛主题的重要研究；原文“publishes important research contributions to a wide range of modern macroeconomic topics”）；
- 北京大学的一篇博士学位论文；
- B站上的一个演讲视频（B站：据其官网介绍，是“中国年轻一代的标志性品牌及领先的视频社区”）；
- Bogleheads论坛上的一个帖子（Bogleheads：据其官网介绍，成员是对投资和个人理财感兴趣的普通人；原文“The Bogleheads are every-day citizens with an interest in investing and personal finance.”）。

视频和音频直接写明是采访、演讲、课程或其他内容。

渠道按以下分类判断：**期刊、学术会议、大学学位论文库、预印本网站、出版社、政府部门、公共机构、研究机构、企业、新闻媒体、个人网站或博客平台、社交媒体、论坛、其他。**

分类只供AI执行时参照，不出现在正式文章中。渠道归入“其他”时，写明具体是什么，并记录为产品问题，在后续版本中补充分类。

渠道介绍取自渠道自己的介绍页面，不能由模型补写；取不到时写“渠道介绍无法确认”。从名称就能看出渠道性质时，可以不写介绍。平台声望不能代替原文核验。

## 六、输出格式与正文使用

### 1. 单个来源的完整说明

```
[编号]
标题：
链接：
来源：
作者：
发布时间：
读到的范围：
是否原始出处：
注明的出处：
追溯情况：
主要内容：
```

- 标题按页面实际标题填写；页面没有标题时，写“（无标题）开头文字：……”；
- 链接是实际核验过的页面；
- 来源按第五章的写法填写；
- 作者按页面实际署名填写；
- 发布时间按页面或正式元数据填写；
- 读到的范围写全文、只有摘要，或部分正文并写明是哪一部分；
- 是否原始出处写是、不是或无法确认；
- 注明的出处写该来源自己写明的内容出处，没有写明时填“未注明”；只在不是原始出处或无法确认时填写；
- 追溯情况由代码根据工作记录生成，写明每一步的时间、操作、链接和结果；只在不是原始出处或无法确认时填写；
- 主要内容写清楚来源主要讲了什么，以及其中与当前正文主张直接相关的内容。

### 2. 本次来源任务结果

```
来源是否可用：
与正文相关的主要内容：
完整来源说明：
工作记录：
```

工作记录每次运行单独保存为一个Notion页面，记录全部检索和页面访问；“工作记录”一项填写该页面的链接。

写作或多来源知识整理流程根据来源是否可用和相关主要内容决定正文怎样采用。用于文章时，正文保留来源编号，完整来源说明可以放在对应正文附近的折叠区块中，供人类核验来源身份、发布环境和相关原文。

## 七、正常结果与后续分支

| 正常结果 | 后续动作 |
| --- | --- |
| 候选页面真实且相关 | 完成来源说明，进入验收。 |
| 候选页面真实但内容无关 | 标记不采用，继续执行对应主张的搜索任务。 |
| URL无效或页面对象不一致 | 候选核验不通过，不进入正式来源；依据已有标题、作者或目录线索继续检索。 |
| 当前页面不是原始出处，或无法确认 | 按第四章第4节追溯原始出处；找到时使用原始出处，找不到时使用最正规的来源，并写明注明的出处和追溯情况。 |
| 只读到摘要或部分正文 | 按第四章第5节处理。 |
| 只找到不够正规的来源 | 状态为“需人工核查”，照常完成来源说明，由人类判断是否采用。 |
| 来源、作者或发布时间部分无法确认 | 如实记录可确认和无法确认的字段，并根据本次任务要求判断整体是否可用。 |
| 完成检索后仍无可靠来源 | 返回“未找到可核验来源”及已完成的检索范围。 |
| 多个真实来源结论冲突 | 分别保留来源相关内容、时间和范围，明确差异，不强行合并。 |

## 八、验收

只有以下条件全部通过，本次来源任务才算完成：

- 已先明确并搜索完整对象；高度相关来源不足时，已经形成完成任务所必需的问题、原因、措施、案例或结果检索方向；
- 每个正式URL都来自允许入口，并已实际访问；
- 页面存在且页面对象与描述一致；
- 不是原始出处或无法确认的来源，都已按第四章第4节追溯原始出处，追溯情况由工作记录生成；
- 只读到摘要或部分正文的来源，它所支持的正文主张在已读到的内容中确实写明；
- 标题、来源、作者和发布时间来自页面或正式元数据；来源写清渠道、内容和渠道性质，渠道介绍有出处；
- 主要内容能够回到来源原文，并与当前主张直接相关；
- 来源结果没有把原文未表达的推测写成来源内容；使用来源结果的写作与审稿Workflow负责检查正文是否歪曲或扩大来源内容；
- 每个候选来源都有可用、不采用、继续追溯、部分可确认、未找到、来源冲突或需人工核查状态；
- 返回未找到前已经完成约定检索动作；
- 合格来源、未采用结果、受限结果、冲突结果和需人工核查结果没有混在一起；
- 来源结果和完整来源说明已经完成。

未通过的项目返回对应正常步骤处理；只有运行环境阻止步骤继续执行时，进入第九章。

## 九、真正的异常处理

| 运行异常 | 处理方法 |
| --- | --- |
| 搜索、网页读取或数据库工具超时、限流或服务故障 | 记录失败工具和位置；按任务风险重试，尝试允许的备用入口；仍失败时保存已完成状态并安全停止受影响部分。 |
| 登录突然失效，或者工具没有读取权限 | 记录失败位置；尝试正式公开入口；不能取得正文时不得声称已经完成原文核验。页面本身需要账号或付费属于正常情况，按第四章第5节处理。 |
| PDF、网页、音视频或其他文件解析失败 | 尝试其他正式格式、OCR、文本版本或可访问副本；保留失败对象和影响范围。 |
| 写入前发现页面内容已经变化 | 停止基于旧内容写入，重新读取最新状态并重新执行受影响的核验。 |
| 结果写入、状态保存或日志记录失败 | 不得宣布完成；保留可恢复信息，重试或请求人类处理，避免重复写入和覆盖。 |
| 备用工具和入口均不可用 | 返回失败位置、已完成范围和未完成范围，本次任务失败或部分完成。 |

异常处理完成后，从被中断的正常步骤继续，并重新执行第八章验收。异常持续高频出现时，应记录为产品问题，分析根本原因，在后续版本中增加预防措施和回归测试。

## 十、完成条件与结束

同时满足以下条件时，本次来源Workflow结束：

- 完整检索对象及实际采用的检索方向均有明确结果；
- 每个候选来源均已进入规定状态；
- 合格来源已经按照第六章格式说明；
- 未采用、部分可确认、未找到、来源冲突和需人工核查的结果已经分别说明；
- 运行异常已经恢复，或已明确失败位置和影响范围；
- 第八章验收全部通过。

本协议交付来源结果后结束。正文写作、人类确认和版本管理由使用来源结果的后续流程负责。
