## 文件职责

- executor.mjs：只做文档版本管理，不读取测试编号、总表或正确答案。
- vt/cases.mjs：普通修改动作、故障配置、预期分支。
- vt/design.json：与本轮总表对应的测试什么、测试错误、正确结果、首次引入版本。
- vt/samples.json：固定样本及存档位置、代码版本与表的明确映射、完整执行器指纹、历史编号下限。
- vt/fixtures.json：固定样本和历史副本的本地只读快照；供纯内存检查及样本漂移检查使用，不是“本轮真实输出”。
- vt/body.mjs：普通正文段落定位、执行事先写定的普通修改。
- vt/faults.mjs：在执行器与底层读写之间制造事故，并记录实际触发情况。
- vt/judge.mjs：不导入执行器；独立核对正文、版本行、历史、实际副本及事故触发。
- vt/run-vt.mjs：读样本、新建测试文档、调用执行器、读回结果、调用judge、按实际版本登记。
- vt/mutate.mjs：在临时目录改坏执行器，用固定内存样本检查事先写定的失败预测；不访问Notion。

## 上传和PR

1. 保留原V4，从确认的V4基线建立修订分支（例如 v4-revision）。原V4已核对执行器指纹见release.json，历史V4提交短号933d3b8。
2. 解压本包，进入doc-version-executor-v4.1目录后，将目录内文件上传至该分支同名位置，不要在仓库根目录再套一层文件夹；点选显示隐藏文件，确保.github/workflows三个文件也上传。不要直接覆盖main，不继续使用V5候选分支。
3. 建立修订分支到main的Pull Request。PR是审查与合并入口，不是上传文件的位置。
4. 在分支验证，确认后才合并。若Actions页面的手动入口暂时不可见，先确认对应工作流已存在于默认分支；不要为了出现按钮而未经审查覆盖main。
5. 若旧分支留有V5文件，必须确认不混入：all-cases、scenarios、scenario-judge、extra-faults、samples-new、preflight等不属于本包。优先从干净V4基线建分支，不把旧文件零散拼进来。

## 测试入口（用户手动启动）

GitHub Actions → VT版本协议测试 → 选择修订分支。

先选择case=VT01，table=auto。实际执行器为v4.1时只能写入v4.1对应表；选v4会在建测试文档之前停止。确认登记位置、编号和输出链接正确后，再选all。不要把正式版本管理的四项输入当成测试总表配置。

- 测试结果：写入版本对应总表；首次引入版本来自固定设计，不随回归版本变化。
- 编号：分页读取全部历史表，包含V5已发生的运行；同一测试跨表接续。一个仓库内登记工作流串行，不能跨账号或复制仓库同时写同一组总表。
- 已经发生的运行不要删除；如因特殊原因删除，须同步维护配置的编号下限。脚本不能从已经彻底删除且无留痕的数据里推断次数。
- 待跑编号如被另一轮占用，脚本停止而非擅自覆盖；核对本轮待跑编号后再启动。
- 如显示“运行已结束但登记失败”，不要直接再跑；先用GitHub结果附件补记本次运行，以免实际运行次数丢失。
- 结果附件保存在GitHub Actions artifacts，登记失败仍尽量保留判定、故障记录及输出页面位置。

## 正式版本管理

Actions → 正式运行：版本管理 → 选择经验证的分支，填写文档ID、版本副本存档父页面ID、本次已确认的操作说明、操作人四项。密钥使用现有NOTION_TOKEN secret；不要写进代码或上传.env。

## 普通附件与历史副本

普通附件子页面不是错误，不因它存在停止，也不移动原附件。新建历史副本仍必须位于指定存档父页面，并独立读回核对父页面。复制时将子页面所有权块转为指向原附件的普通链接，避免把附件移入副本；父文档中的原块保持。只保留附件引用，本轮不冻结附件内部内容、不声称完成多页内容备份。旧版正文中的普通页面链接正常保留。

## 纯内存检查（仅在获准后执行）

运行环境Node.js 24。`node vt/run-vt.mjs --case VT01 --fake`只读随包本地fixtures，在内存假Notion上写入，不访问真实Notion，也不登记总表；结果写本地results。`node vt/mutate.mjs`以相同边界执行全部基线及变异检查。预测不等于实测结果，运行后不对应必须报告，不能改预测来凑通过。

## 已知边界

- Notion多次页面写入不是数据库事务。本包增加了读回及并发正文变化保护，但无法消除外部用户在“最后一次读取到写入之间”修改的竞态；运行期间不要同时编辑同一文档。
- 可完整读取的单页正文及附件引用是本轮范围；接口返回截断会停止，不能冒充完整快照。
- 不自动改建不可用的存档父页面，不自动移动副本到别处。
- 建副本页结果不明确时停止，不盲目重试建页导致多份副本；需要人工核对是否已经建立。后续写入和比对按既定重试上限处理。
- 静态检查不证明接口行为、样本格式兼容或错误恢复已经真实通过；合并前按PR清单验证。
