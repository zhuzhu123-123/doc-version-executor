# doc-version-executor

AI文档工作流的版本管理执行器，以及用来测它的版本协议测试（VT01～VT23）。

## 一、仓库里有什么

分两类：一类是被测的东西，一类是用来测它的工具。

### 1. 被测的：执行器

| 文件 | 作用 |
| --- | --- |
| `executor.mjs` | 执行器。文档改完后由它写版本管理表、建副本、比对副本。平时使用也只用它。Notion 代码页上存有一份逐字一样的存档。 |

### 2. 测试用的工具（都在 `vt/` 里）

| 文件 | 作用 |
| --- | --- |
| `faults.mjs` | 制造错误代码：夹在执行器和 Notion 之间，运行时故意制造事故，比如副本漏一段、版本号写错。执行器不知道它存在。 |
| `judge.mjs` | 判定代码：跑完后对照测试总表的“正确结果”，判通过或失败。按协议单独编写，不用执行器的代码；预期编号在运行前从样本现算（最近成立的版本加一），不写死数字。 |
| `cases.mjs` | 测试配置：23个测试各自要制造什么错误、发什么普通修改请求。 |
| `body.mjs` | 按“正文第几段”定位的小工具：修改请求和制造错误都按位置找段落，不依赖样本里的具体原话。 |
| `samples.json` | 样本对应表：每个测试用哪份原始样本，以及测试文档放在哪一页。 |
| `run-vt.mjs` | 运行脚本：把上面这些串起来，按顺序跑一个测试，结果写进测试总表。 |
| `mutate.mjs` | 改坏执行器检查：把执行器按固定方法改坏10份，每份只改一处，每份都把全部测试在模拟的 Notion 上跑一遍，再和事先写好的预测逐个对照。用来检验测试本身：执行器少做了哪项检查，相应的测试就应该失败。不写测试总表，不改任何真实页面。 |

### 3. 不是代码的文件

| 文件 | 作用 |
| --- | --- |
| `.github/workflows/vt.yml` | 给 GitHub 看的设置：运行“VT 版本协议测试”时执行哪个脚本。 |
| `.github/workflows/mutate.yml` | 给 GitHub 看的设置：运行“改坏执行器检查”时执行哪个脚本。 |
| `.github/workflows/run.yml` | 给 GitHub 看的设置：运行“正式运行：版本管理”时，用填进来的四项运行执行器。 |
| `README.md` | 本说明。 |

## 二、一次测试怎么跑

1. 在“测试文档”页下新建一个测试文档，把原始样本复制进去，再做一次普通修改（固定代码完成，每次改得一样）。原始样本只读不改，后面的步骤都在测试文档上进行。
2. 装上制造错误代码，运行执行器。
3. 读回文档和副本，由判定代码判通过或失败。
4. 在测试总表里写一行：结果、运行时间、执行器版本、存在问题、原始样本、测试文档和本次运行记录的链接。

## 三、需要的 Notion 权限

Notion 连接只能读写加了它的页面和这些页面下面的子页面。页面里的链接不算。需要加连接的只有两页：

- **AI文档工作流｜测试入口**：测试总表在这一页里，要写结果。
- **AI文档工作流｜VT原始样本、测试文档和副本存档**：原始样本、测试文档和副本存档都在这一页下面，要读写。

正式运行时，要做版本管理的文档和它的存档页也要加连接（或者放在已加连接的页面下面）。

执行协议不用加：协议里的规则已经写进执行器代码，运行时不读协议文档。

## 四、怎么运行

- **跑测试**：Actions → VT 版本协议测试 → Run workflow → 填测试编号（如 VT01）或 all。
- **正式运行**：Actions → 正式运行：版本管理 → Run workflow → 填文档编号、存档页编号、本次操作说明、操作人。四项内容由模型在对话里写好，复制进去即可。结果看运行记录最后一行：“结果：版本成立｜第N版”或“结果：版本管理失败｜原因”。
- **检验测试本身**：Actions → 改坏执行器检查 → Run workflow，不用填。结果只在运行记录里显示，最后一行是“结论：全部对得上 ✅”就说明每份改坏的执行器都被预测中的测试发现了。

密钥存在仓库设置的 Secrets 里，名字是 `NOTION_TOKEN`，三项共用。

## 五、执行器 v4 改了什么

- **开始前检查子页面**：文档下面挂着子页面时，副本没法和文档完全一样，执行器在开始前就停下，什么都不写。对应测试 VT23。
- **页面编号取链接最后 32 位**：编号永远在链接最后。三步：去掉“?”和“#”后面的内容；去掉横线；取最后 32 位。这样编号前面带标题里的数字（如“AI-2026-编号”）也能读对。对应测试 VT22。
- 读上一版副本链接（用来算影响位置）也改用同一个读编号的方法。
- 改坏执行器检查新增两份：“不检查子页面”（预测只有 VT23 失败）、“页面编号用旧的认法”（预测只有 VT22 失败）。
